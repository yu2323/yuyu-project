# 灵枢玉简 Lingyu Jade v0.3.0

给 SillyTavern 使用的“世界内设备 / 世界侧窗口”前端扩展原型。当前 UI 仍以修真玉简为皮肤，但 v0.3.0 开始把剧情桥接逻辑与皮肤拆开，为现代手机、星际终端等通用化做准备。

## 当前功能

- 顶部酒馆工具栏“卷轴”入口，带未读角标
- SillyTavern 原生 Popup 主面板，移动端优先
- 首页：地点 / 时辰 / 灵石 / 世界异动
- 灵讯：联系人、未读数、聊天记录、手动发送
- 留影：类似朋友圈的信息流，可点赞、自己发动态
- 坊市：价格 / 库存 / 涨跌状态
- 人物簿：关系、位置、最近活动
- 状态写入当前聊天 `chatMetadata`，不同聊天存档互不串线
- **v0.3.0 新增剧情桥：读取最近正文、调用当前酒馆 API 抽取事实、生成少量世界侧反应，并把关键连续性事实注入下一轮正文上下文**

## v0.3.0｜剧情桥最小闭环

### 正文 → 设备

剧情桥直接读取 SillyTavern `getContext().chat` 中最近 8 条可见 USER / CHAR 正文，不通过 DOM 抓字。

点击玉简顶部新增的“链接”按钮时：

1. 读取最近正文。
2. 调用当前酒馆配置的 `generateQuietPrompt()`，单独发起一次后台请求。
3. 要求模型只抽取已发生、可确认的事实，禁止读取 USER 未外显心理，禁止把旁白信息自动发给角色。
4. 在有直接因果依据时，最多生成 2 个设备侧反应：世界异动 / 消息 / 动态。
5. 更新当前聊天自己的 `chatMetadata`。

### 设备 → 正文

剧情桥通过 `setExtensionPrompt()` 把必要连续性放到正文上下文：

- 使用 `IN_CHAT`
- depth = 1
- system role
- 最多约 1800 字符
- 不把整个朋友圈或聊天记录塞进去
- 每条私密信息尽量携带“可知者”边界

例如 USER 在玉简中给某人发消息，下一轮正文会获得类似：

`USER 已通过设备向“某角色”发送：“……”（可知者：USER、某角色）`

用于让后续剧情记得这件事，而不是让所有角色凭空知道。

### 手动 / 自动

玉简顶部会出现两个桥接按钮：

- 链接图标：手动同步最近正文，一次操作额外调用一次当前 API。
- 闪电图标：自动剧情联动；默认关闭。开启后，每次 `CHARACTER_MESSAGE_RENDERED` 后额外调用一次当前 API。

自动模式默认关闭，避免安装后无提示增加 API 消耗。

## 当前限制

- v0.3.0 只验证“正文 → 状态 → 下一轮正文”的桥是否稳定、是否会串信息。
- UI 文案和默认测试数据仍然是修真玉简皮肤，**尚未完成通用世界初始化**。
- 信息权限目前依靠结构化 `known_by` + 注入约束，是第一版边界；仍需实机观察模型是否出现越权知情。
- 暂不让插件主动改写主聊天消息，也不允许后台模型直接续写正文。
- 自动模式每轮会额外产生一次后台生成请求，应按实际 API 成本决定是否开启。

## 已验证 UI 基线

- v0.2.0：自制 fixed 面板迁移到 SillyTavern 原生 Popup，解决移动端反复开关不稳定。
- v0.2.1：移动端可读性改版，去额外纹理、提高对比、重排首页、重做底部导航。
- v0.2.2：内部高度改为跟随原生 Popup 内容区，中间正文滚动，底部导航固定留在插件内部。

## 文件

- `manifest.json` — 扩展声明
- `bridge.js` — v0.3.0 剧情桥入口；加载 UI 并负责 API / 正文同步
- `index.js` — 玉简 UI、状态与交互逻辑
- `style.css` — 玉简内容样式
- `style-v0.2.2.css` — 手机端 Popup / 底栏 containment 修正
